# 设计说明：为什么是"扩展 + skill + 脚本"三件套

## 1. pi 的扩展机制决定了形态

pi 的内核故意做小：**不带内置 MCP、不带内置手机控制**。给模型加"新能力"只有一条路——写 extension：

```ts
pi.registerTool({ name: "android", parameters: Type.Object({...}), async execute(...) {} })
```

- **Skill**（`SKILL.md`）：纯文本说明书，只影响模型"怎么想、按什么顺序做"，**不能执行任何东西**。
  可以理解为"操作手册"。
- **Extension**（`.ts`）：能够注册工具/命令/事件钩子，是真正的"手脚"。
- **Package**：把上面两者打包，用 `pi install git:...` 分发（本仓库即此形态：
  `extensions/` 与 `skills/` 是 pi 的约定目录，无需额外 manifest）。

结论：**扩展负责"能不能做"，skill 负责"该不该这么做"**。手机控制这种既有强执行、
又有大量经验性判断（先快路径、点完要验证、别信 PSNR）的能力，两者缺一不可。

## 2. 为什么扩展内部不经过 shell

```ts
execFile(adbPath(), ["-s", serial, ...args])   // 而不是 exec(`adb -s ${serial} ...`)
```

- 不经过 shell → 没有引号/转义/路径改写问题（Git Bash 会把 `/sdcard` 改写成 `C:/Program Files/Git/sdcard`）
- 参数边界清晰 → 用户文本（含空格、引号、中文）不需要自己拼转义
- 仍是 adb 自己的 argv 拼接，语义与原生命令一致

## 3. Token 经济：文本树 > 截图

| 观察方式 | 成本 | 信息量 |
|---|---|---|
| `uiautomator dump` + 压缩格式化 | 几十行文本（约几百 token） | 控件文本/ID/坐标/状态，足够定位 |
| `screencap` 1080×2400 | 一张图 ≈ 500KB base64，数万 token | 视觉全貌，但贵 2–3 个数量级 |

所以默认只给 `screen`（文本），`shot` 作为兜底（UI 树没有文字：画布、游戏、纯图像）。
`screen` 还会去重（同 text+id+坐标）、过滤无信息节点、限制行数（默认 80），并可 `query` 二次过滤。

实测观察延迟：`uiautomator dump` **约 2.5–3s/次**。加上决策，"看→点→验"一轮 8–12s。
这决定了 agent 循环必须短，长任务要批量化（见下）。

## 4. 两阶段流水线：把"识图"从同步阻塞变成批量处理

朴素做法：每条视频 → 截图 → 立即读图 → 决定下一步。问题：

- 每条都要一次模型往返（含图像 token），延迟叠加
- 停留时间被识图打断，节奏不可控

改成两阶段：

```
阶段 1（快，纯 adb）：上滑 → 停留 d 秒 → 截图 → 记 TSV（时间/PSNR/Activity/UI文本）
阶段 2（一次）：把 N 张拼成一张长图 → 只读 1 次 → 批量识别 N 条
```

收益（实测 5 条）：采集 29s，全程 3 次工具调用；旧流程需要 10 次调用。
副作用：**采集时无法做"内容相关"的判断**（比如"跳过购物类"）——所以那类判断交给
**不耗图像的 UI 关键词**，在阶段 1 里用 `grep` 完成。

## 5. 验证闭环：每个动作都要有可观测的"证据"

| 动作 | 验证方式 |
|---|---|
| 点击 | 再 `screen` 一次：目标节点消失/新 Activity 出现 |
| 改设置 | `settings get` / `cmd uimode` 回读 |
| 滑动换内容 | 截图 PSNR + 作者/文案 + 顶层 Activity 三者一起看 |
| 打开 App | `dumpsys activity activities \| grep -m1 topResumedActivity` |

只报"命令执行成功"是不够的：`input swipe` 返回 0 并不代表界面真的动了（直播间浮层会吃掉手势），
`am start` 表示成功但任务可能被压到后台。

## 6. 多设备默认拒绝执行

两台以上设备时，未指定 `device` 就直接报错并列出候选。理由很实际：
一条 `input tap` 打错设备，可能就是在别人的手机上误点了转账按钮。
设备标识接受 **serial 子串 / model / codename**，因为无线 adb 重连后端口会变（写死端口必然失效）。

## 7. 安全边界

- 只做"用户明确要求"的写操作；发消息、删除、卸载、改系统开关前必须确认
- 无线 adb 端口只能在局域网 / VPN 内
- 采集下来的截图属于隐私数据：`.gitignore` 里排除了 `out/`，仓库里不带任何真机数据
